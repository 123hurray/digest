别让 AI 直接画视频，让它写代码算出来，视觉推理反而更准

视频生成模型最近多了一个新活，拿它们当视觉推理器用。给模型一张首帧画面和一句文字提示，让它把指定的任务“演”出来，比如把一堆方块按规律排好，或者把图形旋转到指定位置，答案就藏在生成的视频里。这个思路听起来很自然，推理直接发生在画面里，不经过语言和代码。但它到底靠不靠谱，一直没人和另一条路在同等条件下比过。伦敦大学学院的罗德志团队这次做了这个对照，另一条路是让编码智能体写一段程序，把答案视频“算”出来。

对照做得很严。测试集叫 VBVR-Pro-Bench，一共 500 道题，覆盖抽象、感知、空间、变换、知识五类认知任务，每道题都有符号化的标准答案。编码智能体和视频模型拿到完全相同的首帧和提示，用同一套没有改过的规则评分器打分，每道题只有一次尝试，编码智能体还被禁止调用任何图像或视频生成模型。结果是，三款闭源编码智能体分别拿到 0.923、0.894 和 0.893 分，Codex 配 gpt-6-astra 最高，Claude Code 配 Fable 5.1 和 Gemini CLI 配 Gemini 3.1 Pro 紧随其后。最强的视频模型是经过强化学习训练的 VBVR-Pro-Wan2.2-I2V-A14B，得分 0.670，三款编码智能体都比它高出 0.22 以上。23 个能跑起来的开源权重模型里最好的是 GLM-5，得分 0.572，仍然高于除强化学习训练款之外的全部视频模型。

分数之外，论文还打开看了智能体写出的 1385 段解题程序，区分了两种写法。一种叫描绘式程序，程序会真的去读图，定位画面里的元素，找出可迁移的规律，再把规律应用到答案上。另一种叫命题式程序，程序绕过读图，直接把答案数值硬编码进去，表面上答对了，实际上没有做视觉推理。三款闭源智能体在全部五类任务上都领先，说明它们的优势不是某一类题型带来的，而是写代码这条路本身在这些任务上更可靠。

这篇论文的结论有个明确的适用范围，它只针对那些答案能从首帧画面和提示计算出来的任务。视频模型直接在像素里“想”的方式，在这类任务上输给了先写程序再渲染答案的方式。程序合成的优势在于每一步都有明确的符号操作，错了能定位，对了能复用，而像素去噪的推理过程很难拆开检查。至于那些答案没法算出来、只能靠画面感觉的任务，两条路谁更强，这篇论文没有回答。
